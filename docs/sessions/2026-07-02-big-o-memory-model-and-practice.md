# 2026-07-02 - Big O - 메모리 모델과 분류 실습

## 1. 학습 범위

진행한 체크포인트: Week 1, Day 1-2 - "Big O 표기법과 메모리 모델"의 나머지
절반. 이번 세션은 메모리 모델(스택 vs 힙, 참조/역참조, 할당과 해제)을
마무리하고, 실전 감각을 위해 코드 스니펫 3개를 Big O로 분류하는 실습을
진행했다. 이로써 Big O와 메모리 모델 체크포인트가 완전히 마무리됐다.

## 2. 막힌 점 / 헷갈린 점

- 처음엔 "이 주소가 스택이 된다"고 말했음 - "주소는 스택에 있는 참조/변수가
  들고 있는 것"으로 정정. 스택이 담고 있는 건 주소 그 자체가 아니라 그
  주소를 가리키는 참조.
- 중첩 루프 중복 검사 스니펫에서 `len(arr)`를 별도의 루프로 세어 루프 3개
  (O(n^3))로 잘못 판단함 - `len()`은 반복이 아니라 O(1) 호출 1번이라는 점을
  짚어준 뒤 루프 2개(O(n^2))로 정정.
- `arr[len(arr) // 2]`를 "배열 크기가 n이니까 n"이라고 판단해 O(n)으로
  잘못 계산함 - Python 리스트의 `len()`이 O(1)(길이를 메타데이터로 저장)이고
  인덱싱도 O(1)이므로 함수 전체가 O(1)이라는 걸 확인한 뒤 정정. 학습자가
  스스로 "만약 `len()` 자체가 비싼 연산이었다면?"이라는 후속 질문을 던졌고,
  그 경우 함수의 복잡도는 `len()`의 비용을 따라간다고 스스로 옳게 추론함 -
  전체 복잡도는 가장 눈에 띄는 루프가 아니라 가장 비싼 연산이 결정한다는
  일반 규칙을 확인함.
