# Big O 표기법과 메모리 모델

Big O 시간복잡도 표기법(입력 크기에 따라 실행 시간이 어떻게 늘어나는지)과
메모리 모델(실행 중 데이터가 어디에 저장되고 언제 사라지는지)을 다룬다.

[CURRICULUM.md](../../CURRICULUM.md) Week 1, Day 1-2 - 구조별 학습(Array 등)에

## 핵심 개념

Big O는 입력 크기 `n`이 커질수록 알고리즘의 실행 시간(또는 메모리 사용량)이
얼마나 빠르게 늘어나는지를 나타낸다. 정확한 초 단위 시간이 아니라 "증가하는
패턴(모양)"을 나타내는 표기법이다.

메모리 모델은 프로그램 실행 중 값이 어디에 저장되고 언제 사라지는지를 설명한다.
공간은 두 곳이다: **스택(stack)**은 함수 지역 변수를 담고 있으며 엄격한
LIFO(후입선출) 순서로 커지고 줄어든다 (함수를 호출할 때마다 그 함수의 지역
변수가 스택 위에 쌓이고, 함수가 끝나면 자동으로 제거된다). **힙(heap)**은 크기나
생존 기간이 특정 함수 호출에 묶여 있지 않은 값을 담는다. 힙에 저장된 값은 빈
공간 아무 데나 할당되고, 스택에는 그 값의 실제 데이터가 아니라 **참조(reference,
주소)**만 저장된다. 참조를 통해 실제 데이터를 읽어오는 것을 **역참조
(dereferencing)**라고 한다.

## 근거/이유

Big O는 상수 배수는 무시하고, `n`이 커질 때 가장 크게 영향을 미치는 항만 본다.
지금까지 다룬 복잡도 등급:

| 표기 | 모양 | 주로 발생하는 원인 |
|------|------|---------------------|
| O(1) | 상수 | `n`과 무관하게 항상 고정된 횟수만 실행 (예: `arr[3]`) |
| O(log n) | 반씩 줄이기 | 문제를 계속 절반으로 쪼갬 (예: 이진 탐색) |
| O(n) | 선형 | 입력을 한 번 순회 |
| O(n log n) | 선형 x 반씩 줄이기 | `n`번 도는 작업 안에 `log n`짜리 작업이 결합된 경우 (예: 병합정렬, 또는 `n`개 각각에 대해 이진 탐색을 수행하는 경우) |
| O(n^2) | 이차 | 중첩 루프 2개 (예: 모든 쌍을 비교) |
| O(n^3) | 삼차 | 중첩 루프 3개 |

이번 세션에서 바로잡은 오해: "O(n^2)이면 무조건 리팩토링해야 한다"는 고정된
규칙이 아니다. 실제로 `n`이 얼마나 커지는지에 따라 다르다 (n=100이면 괜찮지만
n=10,000,000이면 문제가 된다).

스택에 저장된 값은 함수가 끝나는 즉시 순서대로(LIFO) 자동으로 해제되기 때문에
스택 할당은 빠르고 예측 가능하다. 힙에 저장된 값은 정해진 해제 순서가 없어서,
자동으로 해제되거나(Python은 아무도 참조하지 않는 힙 객체를 참조 카운팅 +
순환 참조용 가비지 컬렉터로 해제) 수동으로 해제해야 한다(C에서는 `malloc()`으로
할당한 것을 프로그래머가 직접 `free()`로 해제해야 하며, 안 하면 프로그램이
끝날 때까지 메모리가 누수된다).

이번 세션에서 바로잡은 또 다른 오해: 전체 시간복잡도는 함수 안에서 **가장 비싼
연산**이 결정하는 것이지, 가장 눈에 띄는 루프 하나만 보고 판단하는 게 아니다.
`len()`은 공짜처럼 보이지만, 만약 O(1)이 아니었다면 그걸 호출하는 함수 전체가
O(n)이 됐을 것이다. Python 리스트는 길이를 매번 세지 않고 메타데이터로
저장해두기 때문에 `len()`이 O(1)로 유지되는 것뿐이다.

## 실전 예시

- **이진 탐색** (O(log n)): 정렬된 리스트에서 "더 크다/작다" 힌트를 받으며
  탐색 범위를 반씩 좁혀가는 것 - 1~100 숫자 맞히기 게임과 같은 원리.
- **병합정렬** (O(n log n)): 배열을 `log n`번 반으로 쪼갠 뒤, 매 단계마다
  전체 `n`개 원소를 훑으며 합친다 - O(n^2) 정렬보다 대규모 데이터에서 왜
  O(n log n) 정렬이 더 빠른지 보여주는 대표 예시.
- **함수에 넘긴 리스트를 변경하는 경우** (메모리 모델): 리스트 인자는 힙
  객체이고 매개변수는 그 객체에 대한 참조일 뿐이므로, 함수 안에서 리스트에
  값을 추가하면 호출한 쪽이 보는 것과 같은 객체가 바뀐다 - 반면 숫자 하나를
  넘기면 스택에서 값 자체가 복사되므로 함수 안에서 바꿔도 호출한 쪽에는
  영향이 없다.

## 쉬운 예시

```python
for i in range(n):        # O(n) - 루프 1개
    ...

for i in range(n):        # O(n^2) - 중첩 루프
    for j in range(n):
        ...
```

반씩 줄이기 감 잡기: 16 -> 8 -> 4 -> 2 -> 1, 4단계 걸림. 2^4 = 16이므로
log 밑 2로 16은 4.

```python
def foo():
    x = 5          # 스택: int처럼 크기가 작고 고정된 값
    y = [1, 2, 3]  # 힙: 리스트 객체 자체는 여기 저장됨;
                   # y라는 이름(참조/주소)은 스택에 저장됨
```

## 핵심 요약

- Big O는 입력 크기 `n`에 대한 "증가 속도"를 나타낸다. 실제 초 단위 시간이
  아니다.
- 중첩 루프는 대략 곱해진다: 루프 1개 = O(n), 중첩 2개 = O(n^2), 중첩 3개
  = O(n^3).
- O(1)은 `n`이 커져도 실행 횟수가 절대 늘어나지 않는다는 뜻이다.
- O(log n)은 문제를 반복해서 절반으로 줄이는 데서 나온다. `n`이 아무리
  커져도 아주 천천히 늘어난다.
- O(n log n) = `n`번 도는 작업 안에 `log n`짜리 작업이 결합되거나, `log n`개
  레벨이 각각 `n`개 전체를 훑는 구조.
- "O(n^2)이면 무조건 리팩토링"은 절대적인 규칙이 아니다 - 실제 `n`의 크기에
  달려있다.
- 전체 복잡도는 가장 눈에 띄는 루프가 아니라 함수 안에서 가장 비싼 연산이
  결정한다.
- 스택: LIFO, 함수 지역 값/참조를 담고, 함수가 끝나면 자동으로 순서대로
  해제됨.
- 힙: 정해진 해제 순서가 없고, 생존 기간이 유동적인 값을 담으며, 필요할 때
  할당되고 자동(Python)이나 수동(`free()`, C)으로 해제됨.
- 힙 값을 가리키는 변수는 값 자체가 아니라 주소를 담고 있다 - 읽으려면 그
  주소를 역참조해야 한다.

## 연습 및 인터뷰 노트

2026-07-02 세션의 Big O 분류 연습 (스스로 정정한 뒤 3/3 정답):

1. 단일 루프에서 `append` + 누적하는 `total`/`items` 패턴 -> O(n).
2. 중첩 루프로 모든 쌍을 비교하는 중복 검사 -> O(n^2) (처음엔 `len(arr)`를
   별도의 루프로 세서 O(n^3)으로 잘못 판단함).
3. `arr[len(arr) // 2]` -> O(1) (처음엔 `len()`이 `n`에 비례한다고 생각해서
   O(n)으로 잘못 판단함; Python에서 `len()` 자체가 O(1)이라는 걸 확인한 뒤
   정정함).
