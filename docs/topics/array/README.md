# 배열 (Array)

메모리에 원소를 연속으로 붙여서 저장하고 인덱스로 접근하는 자료구조를
다룬다. 배열을 활용하는 정렬/탐색 알고리즘은 별도 주제에서 다룬다.

## 커리큘럼 위치

[CURRICULUM.md](../../CURRICULUM.md) Week 1, Day 3-5 - 핵심 자료구조
(Big O/메모리 모델 다음 순서).

## 핵심 개념

배열은 원소를 메모리에 **연속으로(나란히)** 저장하고, 그 순서(인덱스)로
각 원소에 접근하는 자료구조다.

## 근거/이유

원소가 메모리에 연속으로 붙어있기 때문에, 시작 주소만 알면 `i`번째
원소의 주소를 `시작주소 + i * 원소크기`로 바로 계산할 수 있다 - 앞에서부터
세어갈 필요가 없다. 이 덕분에 인덱스로 값을 읽거나(조회) 이미 있는
자리의 값을 바꾸는(수정) 연산은 **O(1)**이다.

반대로 중간에 값을 **삽입**하거나 **삭제**하려면, 그 뒤에 있는 원소들을
전부 한 칸씩 밀거나 당겨야 한다 (연속성을 유지해야 하므로 빈 칸을 남겨둘
수 없다). 그래서 삽입/삭제는 **O(n)**이다 (최악의 경우 맨 앞에서
삽입/삭제할 때 뒤 원소 전부를 옮겨야 함).

정리하면: 배열은 **조회/수정은 빠르고(O(1)), 중간 삽입/삭제는
느리다(O(n))**. 이 트레이드오프 때문에 "조회 위주" 상황엔 배열이
유리하고, "삽입/삭제가 잦은" 상황엔 다른 구조(예: 나중에 다룰 Linked
List)가 더 유리하다.

## 실전 예시

- **학번으로 학생 성적 조회**: 인덱스(학번)만 알면 바로 O(1)로 값을
  찾을 수 있어 배열이 잘 맞는 경우.
- **대기열 앞쪽에서 계속 추가/삭제해야 하는 상황**: 배열로 하면 매번
  나머지 원소를 O(n)만큼 밀어야 해서 비효율적 - 이런 경우는 이후에
  다룰 Linked List 쪽이 더 유리하다 (지금은 이름만 짚고 넘어감).

## 쉬운 예시

```python
arr = [1, 2, 3, 4, 5]

arr[2]        # 조회 - O(1), 주소 계산 한 번
arr[2] = 99   # 수정 - O(1), 이미 있는 자리에 덮어쓰기

arr.insert(2, 99)  # 삽입 - O(n), 인덱스 2 이후 원소를 전부 한 칸씩 뒤로 밈
del arr[2]         # 삭제 - O(n), 인덱스 2 이후 원소를 전부 한 칸씩 당김
```

## 핵심 요약

- 배열 = 메모리에 연속으로 저장하고 인덱스로 접근하는 자료구조.
- 연속 저장 덕분에 `시작주소 + i * 원소크기` 계산 한 번으로 위치를 알 수
  있다.
- 조회/수정(이미 있는 자리 값 바꾸기)은 O(1).
- 삽입/삭제는 O(n) - 연속성을 유지하려고 뒤 원소를 밀거나 당겨야 하기
  때문.
- "삽입 == 덮어쓰기"는 흔한 오해 - 삽입은 기존 값을 지우지 않고 끼워
  넣는 것이라 뒤 원소가 밀려난다.
- 조회가 잦으면 배열이 유리하고, 삽입/삭제가 잦으면 다른 구조가 더
  유리하다.
